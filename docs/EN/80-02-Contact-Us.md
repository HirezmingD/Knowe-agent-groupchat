## When to contact us

Situations where it's appropriate to contact us:

- **You've checked the docs and troubleshooting and still can't solve it** — you've been through the three 60 Troubleshooting pages and the FAQ, and the problem remains;
- **Suspected bug** — behavior doesn't match what the docs describe (for example, a feature doesn't respond when you click it, or the result doesn't match the description);
- **Feature suggestion / feedback** — you want Knowe to work better;
- **Confirmation before an evaluation** — you need to confirm the product's official stance before a procurement, deployment, or compliance evaluation.

Not appropriate: if your issue can be solved through [Before submitting: check these first](#before-submitting-check-these-first), please self-check first — it's very likely faster than waiting for a reply, and it avoids duplicate submissions.

## Before submitting: check these first

Go through these three places in order before submitting — most problems get solved here:

1. **The three 60 Troubleshooting pages** — [Connection and Backend Issues](60-01-Connection-and-Backend-Issues.md) (can't connect, backend errors, port problems), [Model and Runtime Issues](60-02-Model-and-Runtime-Issues.md) (connection test fails, model errors, a member stuck), [Directory and Data Recovery](60-03-Directory-and-Data-Recovery.md) (missing directory, backup and data locations);
2. **The FAQ** — [50 Reference · FAQ](50-04-FAQ.md), quick lookup by topic (models / connection / files / knowledge base / cost);
3. **The Glossary** — [50 Reference · Glossary](50-03-Glossary.md), to make sure you're talking about the same thing (for example, "Approval Card", "Roster", "workspace directory").

If it's still unresolved after the self-check, submit with the template below.

## Issue template: version, system, and reproduction steps

When submitting, please fill in the three blocks below, of which **reproduction steps are required**:

**① Version** — the **version number and build info** in "Settings → Account and Identity → About" (see [30 Configuration · Account and Identity · About: version and build info](30-04-Account-and-Identity.md#about-version-and-build-info)).

**② System** — the operating system and its version (for example, Windows 11 23H2 x64); if networking is involved, you can add the network environment (corporate proxy / direct connection, and so on).

**③ Reproduction steps (required)** — fill in the three segments "what you did → what you expected → what actually happened":

> **What you did**: for example, "in Project A I assigned member B a 'generate a weekly report' task and uploaded the `report.xlsx` attachment".
>
> **What you expected**: for example, "member B reads the attachment and generates the weekly report".
>
> **What actually happened**: for example, "the Task card has been stuck on 'Working' for over 30 minutes with no output".

Additional suggestions: paste the original error text (like "the model doesn't support this format" or "connection lost"), plus the approximate time when the problem happened — it significantly speeds up locating the issue.

## Common questions

**Q: Where do I find the "version" in the problem template?**

"Settings → Account and Identity → About" — the version number and build info are both there (see [About: version and build info](30-04-Account-and-Identity.md#about-version-and-build-info)).

**Q: How do I know whether this is a known problem?**

First go through the three [60 Troubleshooting](60-01-Connection-and-Backend-Issues.md) pages and the [FAQ](50-04-FAQ.md) — known problems and their common fixes are prioritized into the docs; if you've checked all of them and still find no solution, submit with the template.

**Q: How long until I get a reply after sending feedback?**

It follows the actual support channel of the product; the more complete the template is (version, system, reproduction steps), the faster the problem gets located. This page doesn't promise a specific timeframe.
