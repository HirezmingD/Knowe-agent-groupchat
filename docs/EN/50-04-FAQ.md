## Models

**Q: Can the first-launch model configuration guide be skipped?**

No. The forced first-run guide is the mandatory entry — until a usable model is configured, the rest of the UI stays locked (see [02 Installation and System Requirements · First launch: model configuration guide](02-Installation-and-System-Requirements.md#first-launch-model-configuration-guide)).

**Q: Do I need to redo the first-run setup to switch the primary model?**

No. The guide only appears on the very first launch; afterwards, change the provider, model, or Key in Settings → Models and Providers and run a connection test (see [30 Configuration · Models and Providers · Primary model: binding and the connection test](30-01-Models-and-Providers.md#primary-model-binding-and-the-connection-test)).

**Q: Do all members use the same model?**

By default, yes. You can bind an independent model per member, so individual members run on a different one (see [30 Configuration · Per-member model binding: when it's worth it](30-01-Models-and-Providers.md#per-member-model-binding-when-its-worth-it)).

**Q: Where is the API Key stored? Could it be sent somewhere?**

The Key is kept on this machine only, never written to browser storage, and clearable anytime in Settings; Knowe only exchanges requests with the provider of the selected model and depends on no extra account or cloud service (see [API Key security: not written to disk](30-01-Models-and-Providers.md#api-key-security-not-written-to-disk)).

**Q: What if the primary model is unavailable?**

If a fallback model is configured, Knowe automatically falls back; if not, first troubleshoot in Settings → Models and Providers — authentication failure, network unreachable, and insufficient balance / rate limited are the three common causes (see [The fallback model and automatic fallback](30-01-Models-and-Providers.md#the-fallback-model-and-automatic-fallback)); detailed troubleshooting is on [60 Troubleshooting · Model and Runtime Issues](60-02-Model-and-Runtime-Issues.md).

## Connection

**Q: The connection status badge shows something wrong (disconnected / reconnecting) — what should I do?**

First click "Retry" next to the badge to restart the backend; if that doesn't work, check your local network and port occupation. The badge states are explained in [40 Advanced · Ports and the backend: the local running mode](40-04-Environment-Variables-and-Deployment.md#ports-and-the-backend-the-local-running-mode); detailed troubleshooting is on [60 Troubleshooting · Connection and Backend Issues](60-01-Connection-and-Backend-Issues.md).

**Q: What happens if a port is taken?**

The backend auto-avoids to another port — generally no manual handling needed; when troubleshooting, check whether other programs on this machine are using 8080 / 8081 (see [Environment Variables and Deployment Modes · Ports and the backend: the local running mode](40-04-Environment-Variables-and-Deployment.md#ports-and-the-backend-the-local-running-mode)).

**Q: Do I need to set environment variables?**

Most users don't — the default configuration works fine. Environment variables mainly serve advanced users tuning in special environments (proxy, port conflicts, data backup) (see [KNOWE_* environment variables: categories and uses](40-04-Environment-Variables-and-Deployment.md#knowe_-environment-variables-categories-and-uses)).

**Q: You stated a request in the group chat but nothing happens?**

First check whether the connection status badge at the top of the window says **Connected**; if not, click **Retry** to restart the backend (see [20 Guides · Create a Project and Build a Team · Before you begin](20-01-Create-Project-and-Build-Team.md#before-you-begin)).

## Files

**Q: What if the AI can't read a certain format?**

First check whether it's in the supported formats list; if not, convert the content into a supported format (for example, export it as PDF, text, or a spreadsheet) before feeding it, or copy the key content straight into a message (see [20 Guides · Files and Attachments · Which formats are supported](20-05-Files-and-Attachments.md#which-formats-are-supported)).

**Q: Why can't the AI read any file on my computer directly?**

That's the security boundary design: by default the team only reads and writes the workspace directory (the sandbox); attachments are the only exception entrance, and they're read only after you pick them yourself and the app confirms and signs the path (see [The safety guard: only files you picked yourself are read](20-05-Files-and-Attachments.md#the-safety-guard-only-files-you-picked-yourself-are-read)).

**Q: What if the preview can't open some files?**

First check whether the file type is in the supported list and whether the file itself is corrupted; preview is only for viewing — to modify a file, use "Reveal in File Explorer" and open it with your own tool (see [20 Guides · File Preview Window · Rendering by file type](20-08-File-Preview-Window.md#rendering-by-file-type)).

**Q: Can I undo a file I dragged in by mistake?**

Before sending, click "Remove" on the attachment block in the composer; after sending, it stays in the chat stream as a message, and you can handle it with the message operations (Quote / Forward / Favorite / Copy) (see [20 Guides · Files and Attachments · Adding attachments: pick or drag](20-05-Files-and-Attachments.md#adding-attachments-pick-or-drag)).

## Knowledge base

**Q: Is knowledge produced automatically?**

What's recorded automatically is **memory** (the process); **knowledge is distilled** — it needs to be refined from the project process and goes through curation: pending assets only take effect after you approve them (see [Lifecycle: Active, Pending review, Retired](20-06-Knowledge-Base-and-Skill-Packs.md#lifecycle-active-pending-review-retired)).

**Q: What exactly is the difference between the knowledge base and memory?**

Memory = process (who said what, did what, what the result was); knowledge = distilled (reusable preferences, practices, pitfalls, facts, decisions). A comparison table is in [10 Core Concepts · Memory and Context · Knowledge base and memory: division of labor](10-05-Memory-and-Context.md#knowledge-base-and-memory-division-of-labor).

**Q: Can deleted knowledge be recovered?**

Retired assets can be restored; **permanent deletion is irreversible** — always confirm before doing it (see [40 Advanced · Knowledge Curation · Permanent delete: irreversible](40-01-Knowledge-Curation.md#permanent-delete-irreversible)).

**Q: Can project knowledge be promoted to global knowledge?**

Yes — **change the scope** on the knowledge card, switching it from "project" to "global" (see [Two scopes: global and project](20-06-Knowledge-Base-and-Skill-Packs.md#two-scopes-global-and-project)).

**Q: What if a skill pack breaks or I want to replace it?**

System skills are immutable; project-experience skills are curatable; third-party skill packs can be uninstalled and reinstalled, following their own lifecycle (see [40 Advanced · Skill Pack Management](40-02-Skill-Pack-Management.md)).

**Q: Does the Coordinator really know everything I say in a DM?**

Yes. In-project DM content is written back to project memory, and the Coordinator always keeps the whole picture — "DMs are not private" is one of Knowe's explicit boundaries (see [20 Guides · Group Chat and DMs · "DMs are not private": boundary explanation](20-04-Group-Chat-and-DM.md#dms-are-not-private-boundary-explanation)).

## Cost

**Q: What currency are the costs shown in?**

RMB (¥). The usage dashboard's scope is the date range you selected, and it counts the model calls that happened locally (see [20 Guides · Token Usage and Cost · How cost is calculated](20-09-Token-Usage-and-Cost.md#how-cost-is-calculated)).

**Q: Why is one member's cost especially high?**

Drill down in the breakdown table's "by member" tab to see how many tasks they were assigned, how many files they were fed, and how long they kept working; then switch to "by model" to see which model they use, and you can pin down the cause (see [The breakdown table: by model / by member](20-09-Token-Usage-and-Cost.md#the-breakdown-table-by-model--by-member)).

**Q: How do I bring the cost down?**

See "Common ways to save tokens": keep the team just big enough, archive idle members, stop stuck members in time, write clear acceptance criteria into the instruction, and reuse knowledge to cut repetition (see [Common ways to save tokens](20-09-Token-Usage-and-Cost.md#common-ways-to-save-tokens)).
