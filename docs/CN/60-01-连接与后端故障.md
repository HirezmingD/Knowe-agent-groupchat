# 60 故障排除 · 连接与后端故障

> **摘要**：Knowe 是**本地运行**的应用：窗口顶部有**连接状态徽章**，显示应用与本地后端之间的连接情况——正常工作时是「已连接」。本页按「症状 → 排查 → 解决」讲清三类连接 / 后端问题：徽章异常（连接中 / 重连中 / 已断开等）怎么办、后端崩溃后如何自动重启与手动「重试」、端口被占用时会发生什么。多数情况下，点一下徽章旁的「重试」就能解决。

## 连接状态徽章：先看懂它

徽章在**窗口顶部（右上角）**，是应用与本地后端之间连接的实时指示，有**连接中 / 已连接 / 重连中 / 已断开等状态**（具体状态集以产品实际为准，见[40 高级功能 · 端口与后端：本地运行形态](40-04-环境变量与部署形态.md#端口与后端本地运行形态)；术语定义见[50 参考 · 术语表](50-03-术语表.md)）。

- **正常工作的标志是「已连接」**——发消息、派活前扫一眼徽章，是最快的自查；
- 徽章不是「已连接」时，群里发了需求可能迟迟没人回应——先处理徽章，再谈别的（与[20 使用指南 · 创建项目与组建团队 · 开始之前](20-01-创建项目与组建团队.md#开始之前)的提示同口径）。

## 症状一：徽章断线或一直重连

**症状**：徽章显示「重连中 / 已断开」等状态，长时间回不到「已连接」；群里发了需求迟迟没人动。

**排查**（按顺序）：

1. 先点徽章旁的「**重试**」重启后端——这是第一步，多数情况就此解决（处理顺序同[50 参考 · FAQ · 连接](50-04-常见问题FAQ.md#连接)）；
2. 仍不行，检查本机网络是否正常：是否断网、是否在公司代理环境需要放行到模型服务商的 HTTPS 出站（见[02 安装与系统要求 · 网络要求](02-安装与系统要求.md#网络要求)）；
3. 再检查是否有其他程序占用了后端端口（见下文[症状三](#症状三端口被占用)）。

**解决**：点「重试」后徽章通常回到「已连接」；若反复断线，按「网络 → 端口」两条线继续排查。

## 症状二：后端崩溃（或根本没起来）

**症状**：徽章显示「已断开」或一直停在「连接中」；操作无响应。

**排查**：Knowe 应用自带后端进程（默认 WS 8080 / HTTP 8081，见[40 高级功能 · 端口与后端：本地运行形态](40-04-环境变量与部署形态.md#端口与后端本地运行形态)）。后端异常时应用会**自动重启（自动拉起）**它——先等几秒，看徽章是否自己恢复「已连接」。

**解决**：如果自动重启没有生效，点徽章旁的「**重试**」手动重启后端。重启只是重新拉起本地后端进程，不影响本机数据——数据都在安装目录的 `data/` 与 `Logs/`（见[40 高级功能 · 数据目录：data 与 Logs](40-04-环境变量与部署形态.md#数据目录data-与-logs)）。

## 症状三：端口被占用

**症状**：怀疑是端口冲突导致的后端起不来或反复断线。

**排查**：后端在本机运行，默认使用 **WS 8080 / HTTP 8081** 端口；被占用时会**自动避让**到其他端口，一般无需手动处理（见[40 高级功能 · 端口与后端：本地运行形态](40-04-环境变量与部署形态.md#端口与后端本地运行形态)）。排障时留意本机是否有其他程序（本地开发服务、其他应用等）占用这两个端口。

**解决**：一般无需处理——自动避让即可。如果确认某个程序长期占用 8080 / 8081 且影响使用，停掉占用程序后再点「重试」重启后端。

## 常见问题

**问：为什么点「重试」了还是连不上？**
按症状一的顺序继续排查：先确认本机网络正常（能访问模型服务商 API，见[02 安装与系统要求 · 网络要求](02-安装与系统要求.md#网络要求)），再看是否有程序占用 8080 / 8081（见[症状三](#症状三端口被占用)）。

**问：徽章一直「连接中」要等多久？**
正常应该很快进入「已连接」；长时间停留在「连接中 / 重连中」，按症状一、症状二依次排查。

**问：断线会不会丢数据？**
不会。Knowe 的数据都在本机（安装目录下的 `data/` 与 `Logs/`，见[40 高级功能 · 数据目录](40-04-环境变量与部署形态.md#数据目录data-与-logs)），不依赖云服务；断线影响的是与本地后端的实时连接，不是数据本身。
