## 为什么项目需要记忆

[用聊天指挥一支 AI 团队](10-01-用聊天指挥一支AI团队.md) 里说过，Knowe 解决传统 AI 助手的三个痛点，其中一个是**上下文断裂**：每次新开对话都要从头解释背景，聊长了模型就忘。

项目记忆就是针对这个痛点的设计。一个项目从建群到收尾可能持续数天、横跨几十次对话，如果每次打开都「失忆」，团队就永远是新手。Knowe 的做法是：**项目自带记忆，团队在项目里发生的每一件事，都沉淀为这个项目的上下文。**

记忆是自动发生的，不需要你手动「保存」——你发消息、确认审批卡、成员工作、提交报告，都会写进项目记忆。

## 项目记忆的三层结构

项目记忆不是一个大筐，而是分三层，各司其职：

```
            项目记忆（随项目走，跨回合保持）
┌──────────────────────────────────────────────┐
│  最近活动（最新消息与动作，短期完整保留）            │ ← 优先装进上下文窗口
├──────────────────────────────────────────────┤
│  滚动摘要（旧活动压缩成摘要，持续更新）              │ ← 常驻上下文，保持全局感
├──────────────────────────────────────────────┤
│  历史活动段（更早的完整记录，按段归档，可回溯）       │ ← 需要时翻出来
└──────────────────────────────────────────────┘
```

| 层 | 装什么 | 作用 | 何时被使用 |
|:--|:--|:--|:--|
| **最近活动** | 最近的消息、审批确认、成员工作过程 | 精确还原「眼下正在发生什么」 | 每次回复都依赖，优先装入 |
| **滚动摘要** | 更早活动的压缩摘要，随时间推进持续更新 | 保持对项目整体进展的把握，不因内容变长而丢背景 | 常驻上下文 |
| **历史活动段** | 更早的完整记录，按时间段归档 | 需要核对细节时的「原始档案」 | 需要回溯时按需读取 |

理解三层结构的关键：**记忆不是「全记住」，而是「分层存取」。** 最新、最相关的内容精确保留；旧内容压缩成摘要，保住全局感；更早的内容归档存好，需要时再翻。这样既不会因记忆无限膨胀拖慢每次回复，也不会真正丢东西。

## 私聊内容为何写回项目

在 Knowe 里，你可以双击花名册里的成员，进入**群内私聊**（`dm:项目:成员`）——比如单独给某个成员补充背景、给项目经理交代不便在群里展开的事。

**但私聊不隐秘**：私聊内容同样会**写回所属项目的记忆**，项目经理始终知道私聊里发生了什么。

为什么这样设计？三个原因：

1. **项目是一个整体**——私聊是「项目内的私下沟通」，不是独立于项目之外的秘密通道。它和群聊一样属于这个项目的上下文；
2. **团队协作需要信息完整**——如果你在私聊里给了成员关键背景，项目经理却不知道，拆解和核对就会失真。写回项目，才能保证总管掌握全局；
3. **避免「黑箱沟通」**——私聊不隐秘，等于从机制上杜绝了「绕过项目经理达成约定」的可能。

> **边界**：这条规则针对**项目内的私聊**（`dm:项目:成员`）。你和知知的平台私聊不属于任何项目，那是独立的接待通道。私聊、记忆与权限边界的更多细节见[40 高级功能 · 私聊、记忆与权限边界](40-03-私聊记忆与权限边界.md)，「私聊不隐秘」的操作面见[20 使用指南 · 群聊与私聊 · 「私聊不隐秘」：边界说明](20-04-群聊与私聊.md#私聊不隐秘边界说明)。

## 知识库与记忆的分工

记忆和知识库很容易混为一谈，其实分工很清晰：

> **记忆 = 过程，知识 = 沉淀。**

| 维度 | 项目记忆 | 知识库 |
|:--|:--|:--|
| 内容 | **过程**：谁说了什么、做了什么、结果如何 | **沉淀**：可复用的偏好、做法、坑、事实、决策 |
| 产生方式 | 自动记录，无需干预 | 从项目过程里**提炼**出来，需要策展（待审 / 批准 / 驳回） |
| 生命周期 | 随项目滚动：新活动进来，旧活动压成摘要、归档 | 长期有效，可退役、可删除、可跨项目复用 |
| 谁维护 | 系统自动 | 你（或经你批准）策展 |
| 作用范围 | 当前项目的上下文 | 分「全局知识 / 项目知识」两级作用域 |

一个例子：成员在项目里发现「某框架的某个版本有已知 bug」——这件事作为**过程**进了记忆；如果你批准把它提炼成一条**知识资产**（类型是「坑」），它就进入知识库，下次同类项目可以直接引用，不必再踩一遍。详见[20 使用指南 · 知识库与技能包](20-06-知识库与技能包.md)。

## 跨回合上下文如何保持

把上面几节串起来，就是跨回合上下文保持的完整链条：

1. **写入**——群聊消息、审批确认、成员工作过程、私聊内容，自动写回项目记忆；
2. **分层**——最近活动精确保留，旧活动压缩成滚动摘要，更早的归档为历史活动段；
3. **读取**——每次项目经理或成员回复时，先装载「最近活动 + 滚动摘要」获得当前上下文，需要细节时再回溯历史段；
4. **沉淀**——值得长期复用的部分，经你策展进入知识库，成为团队的能力而不是一段过程。

所以你可以放心地**隔几天再回来继续**：打开项目群聊，说一句「继续上次的」，团队能接上——因为项目的记忆跟着项目走，不跟着某一次对话走。

> **提示**：记忆的颗粒度与隐私边界（哪些内容会被脱敏、记忆投影里包含什么）见[80 支持 · 安全与隐私](80-01-安全与隐私.md)。
