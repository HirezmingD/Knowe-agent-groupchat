# 30 配置 · 模型与提供方

> **摘要**：模型是团队干活的大脑。本页讲清 Knowe 里模型怎么绑定、怎么换：**主模型**是默认的干活大脑（含连接测试与首次启动的强制引导）；**辅助模型**是主模型不可用时的自动兜底；**按成员绑定模型**让不同成员跑在不同模型上（附「何时值得用」）；最后是 **API Key 的安全说明**——只在本机以 Windows DPAPI 加密保存、不写入浏览器存储、随时可清除。

## 主模型：绑定与连接测试

**主模型**是团队的默认模型：不做特殊设置时，所有成员都用它干活——读项目、拆任务、写代码、核对成果，绝大部分「想」的部分都跑在主模型上。

在**「设置 → 模型与提供方」**里，你可以随时更换主模型的三要素：

- **提供商**——Knowe 内置 20 余家提供方（DeepSeek、Z.AI / GLM、Kimi / Moonshot、Qwen Cloud、MiniMax、StepFun、Tencent TokenHub、OpenRouter、Anthropic、OpenAI、Google AI Studio、xAI、NovitaAI、Hugging Face 等），列表见[02 安装与系统要求 · 首次启动：模型配置引导](02-安装与系统要求.md#首次启动模型配置引导)；
- **模型**——选定提供商后，从其支持的模型列表中选择一个；
- **API Key**——该提供商的密钥，安全边界见下文[API Key 的安全说明（系统加密落盘）](#api-key-的安全说明不落盘)。

换完先跑一次**连接测试**，确认 Key 与网络都可用，再让团队用起来。

![](docs/assets/S39-设置 → 模型与提供方.png)

**连接测试失败怎么办**：测试失败会给出具体原因，常见三类：

| 原因 | 含义 | 处理 |
|:--|:--|:--|
| **认证失败** | API Key 错误或失效 | 检查 Key 是否完整、有无前后空格，更换后重测 |
| **网络不可达** | 连不上厂商 API | 检查网络与代理放行，见[02 安装与系统要求 · 网络要求](02-安装与系统要求.md#网络要求) |
| **余额不足 / 被限流** | 厂商侧限制 | 到厂商控制台查看额度和限流状态 |

> 详细排查步骤见[60 故障排除 · 模型与运行故障](60-02-模型与运行故障.md)。

## 首次启动：强制引导

第一次打开 Knowe 时，**必须完成主模型配置才能进入**——这是**强制引导**（First-run model gate）：背景雾化，其余界面全部锁定，只有配置卡片可以操作；不配置完，其余 UI 全部锁定。

引导卡片顶部先选**界面语言**（中文 / English），下方是模型配置表单，带三步指示器：

> `1 · 选择与填写  ›  2 · 连接测试  ›  3 · 进入`

- **第 1 步 · 选择与填写**——选提供商 → 选模型 → 填 API Key → 点「确定」封存配置；
- **第 2 步 · 连接测试**——封存后自动发起测试，也可点「测试并应用」手动重测；通过后显示类似「连接已通过，正在应用设置 · 320ms」的结果；
- **第 3 步 · 进入**——「进入 Knowe」按钮亮起，点击进入主界面，引导退场、界面解锁。

> 完整界面细节见[02 安装与系统要求 · 首次启动：模型配置引导](02-安装与系统要求.md#首次启动模型配置引导)；[01 快速开始 · 开始之前](01-快速开始.md#开始之前)也要求先完成这一步。首启引导完成的其实就是「主模型绑定」——它与本页的设置入口是同一套配置，之后在「设置 → 模型与提供方」里改即可，无需重走引导。

## 辅助模型与自动降级

主模型之外，Knowe 支持配置一个**辅助模型**作为兜底：当主模型暂时不可用时（如厂商侧限流、网络波动、Key 失效），**自动降级**到辅助模型继续干活，避免团队因为主模型故障而卡住。

要点：

- 辅助模型在「设置 → 模型与提供方」里配置，与主模型并列，同样需要选择提供商、模型与可用的 API Key；
- 平时干活仍以主模型为准，辅助模型只在主模型不可用时顶上；
- 对可靠性要求高的场景，建议配一个与主模型**不同厂商**的辅助模型——把「单一提供方故障」的影响分散掉。

## 按成员绑定模型：何时值得用

默认情况下，整个团队共用主模型。你也可以给**个别成员绑定独立模型**：在「设置 → 模型与提供方」里按成员设置，之后这位成员干活时使用绑定模型，其余成员仍用主模型。

什么时候值得用？两条最实用：

- **成本分层**——让高价值任务用好模型、低价值任务用更省的选择。配合[20 使用指南 · Token 用量与费用 · 明细表](20-09-Token用量与费用.md#明细表按模型--按成员)的「按成员」Tab，先定位成本大头（哪位成员、跑在哪个模型上），再决定给谁换更合适的模型；
- **扬长避短**——不同模型在不同类型任务上的表现各有侧重，可以给某类角色绑定更擅长的模型，让「人尽其才，模型尽其用」。

> **注意**：按成员绑定模型只改变这位成员背后跑的模型，不改变审批与验收流程——派活、核对、汇报照旧（见[20 使用指南 · 派活与验收](20-03-派活与验收.md)）。

## API Key 的安全说明（系统加密落盘）

- **仅保存在本机**——界面说明为「用于调用所选模型，仅保存在本机」，Knowe 只在所选模型提供方之间收发请求，不依赖任何额外账号或云服务（见[02 安装与系统要求 · 系统要求](02-安装与系统要求.md#系统要求)）；
- **系统加密落盘**——设置文件中的 Key 使用当前 Windows 用户范围的 DPAPI 加密；整份设置投影还带受 DPAPI 保护的完整性摘要，离线篡改提供商地址或密文会被拒绝。主文件和加密备份同时无法验证时，设置接口会 fail closed，不会用空默认值覆盖原文件；
- **不写入浏览器存储**——API Key 不落 localStorage，浏览器存储里没有你的密钥；
- **不进入 Agent 终端**——模型生成的 Shell/Python 进程使用最小环境，不继承模型 Key、GitHub/npm token 或其他宿主凭据；
- **随时可清除**——在「设置 → 模型与提供方」里可以清除已保存的 Key；
- **界面进程隔离**——Knowe 的界面进程开启 contextIsolation、渲染进程无 Node 能力，界面层无法直接访问系统资源；
- **界面脱敏**——界面自然语言里成员内部 id、内部路径一律脱敏；涉及 Key 的画面同样遵循打码/留空规范（见本页截图规范）。

> **保护边界**：DPAPI 防止设置文件被离线复制后直接读出 Key，但不能防御已经以同一 Windows 用户身份运行的恶意程序，也不能清除旧版本曾留下的磁盘历史或系统备份。若旧版本中用过高价值 Key，升级并确认迁移成功后仍建议在提供商控制台轮换一次。

## 常见问题

**问：首次启动的引导能跳过吗？**
不能。首启强制引导是必经入口——不配置完，其余 UI 全部锁定（见[02 安装与系统要求 · 首次启动：模型配置引导](02-安装与系统要求.md#首次启动模型配置引导)）。

**问：换主模型要重新走首启引导吗？**
不用。首启引导只在第一次进入时出现；之后换提供商、模型或 Key，直接在「设置 → 模型与提供方」里改，改完跑一次连接测试即可。

**问：所有成员都用同一个模型吗？**
默认是。你可以按成员绑定独立模型，让个别成员用别的模型。

**问：API Key 存在哪里？会不会被传走？**
Key 仅保存在本机，设置文件里是 Windows DPAPI 加密密文，并且不写入浏览器存储；在设置里可以随时清除。Knowe 只在所选模型提供方之间收发请求，不依赖任何额外账号或云服务（见[02 安装与系统要求 · 系统要求](02-安装与系统要求.md#系统要求)）。

**问：主模型不可用时怎么办？**
配置了辅助模型的话，主模型不可用时会自动降级；没配置的话，先在「设置 → 模型与提供方」里排查修复（认证失败 / 网络不可达 / 余额不足被限流三类原因见上），详细排障见[60 故障排除 · 模型与运行故障](60-02-模型与运行故障.md)。
