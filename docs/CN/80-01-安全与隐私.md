# 80 支持 · 安全与隐私

## 本页为谁而写

你未必是 Knowe 的日常操作者，而是需要判断「让 AI 团队在自己的电脑上干活，数据与权限边界是否可控」的人——管理者、采购评估者，或首次引入 Knowe 的 IT / 合规同事。本页把 Knowe 的数据与权限边界整理成一组「数据与权限边界」问答，主线是四件事：

- **数据存在哪**——哪些落在本机、哪些不在安装目录里；
- **谁能看到**——数据谁可访问、哪些内容会发给模型、发给谁；
- **会不会上传**——Knowe 有没有云端、什么才会离开你的机器；
- **边界在哪**——AI 能碰哪些文件、界面展示如何脱敏。

每条结论都指向正文页面，需要时顺着链接看机制与操作细节。

## 数据存哪：三处各归各

Knowe 的数据都在本机，三处目录要分清（口径见[40 高级功能 · 数据目录：data 与 Logs](40-04-环境变量与部署形态.md#数据目录data-与-logs)与[60 故障排除 · 数据在安装目录的哪里](60-03-目录与数据恢复.md#数据在安装目录的哪里)）：

| 目录 | 存放什么 | 位置 |
|:--|:--|:--|
| **`data/`** | 应用数据：聊天记录、项目数据 | 安装目录下 |
| **`Logs/`** | 日志 | 安装目录下 |
| **工作区目录** | 团队产出的文件 | 你建项目时自选的目录，**不在安装目录里** |

决策者关心的「哪些留下、哪些删掉」，三条要点：

- **备份**：想备份数据，备份安装目录里的 `data/` 与 `Logs/` 即可；
- **卸载**：默认保留 `data/` 与 `Logs/`（重新安装可恢复）；**取消勾选则连数据一起删除、不可恢复**（见[02 安装与系统要求 · 卸载与数据保留](02-安装与系统要求.md#卸载与数据保留)）；
- **卸载不会删你的项目文件夹**：工作区目录由你自选、不在安装目录里，卸载不影响其中的文件（同上）。

## 哪些内容会发给模型：消息、附件与记忆投影

Knowe 是**本地运行**的应用：模型请求从本机直接发给**你所选的模型提供方**（见[02 安装与系统要求 · 网络要求](02-安装与系统要求.md#网络要求)），不经 Knowe 中转、不依赖 Knowe 云服务。发给模型的内容，由你主动产生的输入构成：

- **消息**——你发的每条消息，都会作为模型调用内容发出；
- **附件**——你亲手拖进聊天输入区的文件：图片走多模态直读，其余打包为文件内容块发给模型（见[20 使用指南 · 文件与附件 · 附件如何被 AI 读取](20-05-文件与附件.md#附件如何被-ai-读取)）；
- **记忆投影**——为了让模型「记得项目」，每次回复还会装载项目记忆的投影，按需分层（口径见[10 核心概念 · 项目记忆的三层结构](10-05-记忆与上下文.md#项目记忆的三层结构)）：

| 记忆投影 | 装载方式 | 作用 |
|:--|:--|:--|
| **最近活动** | **每次回复都装载** | 最新消息与动作，精确还原「眼下正在发生什么」 |
| **滚动摘要** | **每次回复都装载**（常驻上下文） | 更早活动的压缩摘要，保持对项目整体进展的把握 |
| **历史活动段** | **按需读取** | 更早的完整记录，需要核对细节时才回溯 |

一句话总结：**每次回复都带「最近活动 + 滚动摘要」的当前上下文；更早的完整历史不随每次回复全量发出，只在需要时按段回溯。** 这样既不丢背景，也不会把整个项目的全部历史反复发给模型。

## Key 与凭证安全：只在本机

（口径见[30 配置 · 模型与提供方 · API Key 的安全说明（系统加密落盘）](30-01-模型与提供方.md#api-key-的安全说明不落盘)）

- **仅保存在本机**——界面说明为「用于调用所选模型，仅保存在本机」；Knowe 只在所选模型提供方之间收发请求，**不依赖任何额外账号或云服务**（见[02 安装与系统要求 · 系统要求](02-安装与系统要求.md#系统要求)）；
- **Windows DPAPI 加密**——Key 以当前用户范围的 DPAPI 密文写入设置文件，并用受保护摘要认证提供方、模型、地址与密文的组合；主文件和加密备份均无法验证时，设置 fail closed；
- **不写入浏览器存储**——API Key 不落 localStorage，浏览器存储里没有你的密钥；
- **不进入 Agent 进程**——模型生成的终端进程不继承模型 Key 或其他宿主 token；
- **可随时清除重填**——在「设置 → 模型与提供方」里可以清除已保存的 Key 并重新填写；
- **界面进程隔离**——Knowe 的界面进程开启 contextIsolation、渲染进程无 Node 能力，界面层无法直接访问系统资源。

## 脱敏机制：你看到的是可读信息

脱敏处理的是**内部标识**，让你看到的是可读信息而不是机器标识（口径见[40 高级功能 · 私聊、记忆与权限边界 · 哪些内容会被脱敏](40-03-私聊记忆与权限边界.md#哪些内容会被脱敏)）：

- **成员内部 id**——界面自然语言里一律脱敏，你看到的是成员名字，不是内部标识；
- **内部路径**——同样的规则：界面展示可读路径，内部路径不直接暴露；
- **界面 Key 画面**——涉及 Key 的画面遵循打码 / 留空规范（见[模型与提供方 · API Key 的安全说明](30-01-模型与提供方.md#api-key-的安全说明不落盘)与[30 配置 · 账户与身份 · 关于页](30-04-账户与身份.md#关于页版本号与构建信息)）；
- **工程层 contextIsolation**——渲染进程不直接持有 Node 能力，界面层无法绕过应用边界直接操作本机资源，这是 Knowe 隐私设计的另一道边界。

注意：脱敏针对的是**内部标识**，不是你的聊天内容——聊天内容按项目记忆的规则存放与使用（见[10 核心概念 · 记忆与上下文](10-05-记忆与上下文.md)）。

## 沙箱边界：AI 出不去，附件是例外入口

（口径见[10 核心概念 · 项目与工作区 · 工作区目录：AI 的沙箱](10-03-项目与工作区.md#工作区目录ai-的沙箱)与[20 使用指南 · 文件与附件 · 安全护栏](20-05-文件与附件.md#安全护栏只有你亲手选的文件才会被读取)）

- 团队（项目经理核对、成员执行）读取和写入文件，**只发生在工作区目录之内**；目录之外的任何文件，AI 默认读不到、也写不了；
- 模型生成的 Shell 与 Python 进程通过 Windows 原生执行容器运行：工作区是唯一可写根目录，默认无网络；如果操作系统版本、文件系统或原生探测不满足要求，终端直接不可用，不会退回宿主 Shell；
- 当前固定使用的 MXC 0.7 是微软早期预览。底层 AppContainer/Job 属于真实的操作系统强制隔离，Knowe 也增加了路径、链接、资源和逃逸回归门禁，但它不是虚拟机级隔离；真正敌对的未知代码仍应放在一次性虚拟机中运行；
- **你亲手拖进聊天输入区的附件是例外入口**——而且只有经应用「亲眼确认并签名」的路径才会被读取，防止被诱导去读任意文件；
- 一句话：**你圈多大的地，团队就在多大的地里干活。** 想额外给团队看某个文件，你亲手把它拖进去即可。

## 常见问题（面向决策者）

**问：数据会被上传到 Knowe 服务器吗？**
不会。Knowe 是本地运行的应用，数据都在本机（`data/` 与 `Logs/`），不依赖 Knowe 云端账号或云服务（见[02 安装与系统要求 · 网络要求](02-安装与系统要求.md#网络要求)）。唯一离开本机的内容，是你主动发出的模型请求——它直接从本机发给你所选的模型提供方。

**问：聊天内容会发给哪些模型？**
只发给你在「设置 → 模型与提供方」里配置的模型——主模型、辅助模型（主模型不可用时自动兜底）、以及按成员绑定的模型（见[30 配置 · 模型与提供方](30-01-模型与提供方.md)）。Knowe 不会把内容发给未配置的提供方。

**问：API Key 泄露了怎么办？**
先到**模型提供方的控制台**吊销或更换密钥，使旧 Key 失效；再回到「设置 → 模型与提供方」清除并重新填写新 Key。Key 在设置文件中受 Windows DPAPI 保护且不落 localStorage；若从旧的明文存储版本升级，完成迁移后也建议主动轮换一次（见[API Key 的安全说明（系统加密落盘）](30-01-模型与提供方.md#api-key-的安全说明不落盘)）。

**问：成员能碰我机器上哪些文件？**
默认只有工作区目录。团队读写只发生在这一个目录里，「出不去」；附件是你亲手放行的例外入口，且只有经应用确认并签名路径的文件才会被读取（见[安全护栏：只有你亲手选的文件才会被读取](20-05-文件与附件.md#安全护栏只有你亲手选的文件才会被读取)）。**AI 不会自己去读你机器上的任意文件。**

**问：删除项目 / 卸载后数据去哪？**
项目不需要了，项目记录与聊天记录仍在本机 `data/`，由你处置——归档团队、保留目录即可（见[10 核心概念 · 项目与工作区](10-03-项目与工作区.md)）。卸载时默认保留 `data/` 与 `Logs/`（重新安装可恢复）；取消勾选则连数据一起删除、**不可恢复**；工作区目录不在安装目录里，卸载不影响其中的文件（见[02 安装与系统要求 · 卸载与数据保留](02-安装与系统要求.md#卸载与数据保留)）。
