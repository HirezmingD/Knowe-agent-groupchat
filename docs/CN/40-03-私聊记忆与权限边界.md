# 40 高级功能 · 私聊、记忆与权限边界

## 私聊内容为何写回项目记忆

Knowe 里你可以双击花名册成员进入**群内私聊**（`dm:项目:成员`），单独给某个成员补充背景（入口见[20 使用指南 · 群聊与私聊 · 群内私聊](20-04-群聊与私聊.md#群内私聊双击花名册成员)）。**私聊不隐秘**——私聊内容会写回所属项目的记忆，项目经理始终知道私聊里发生了什么。

为什么这样设计？三个原因（详见[10 核心概念 · 记忆与上下文 · 私聊内容为何写回项目](10-05-记忆与上下文.md#私聊内容为何写回项目)）：

1. **项目是一个整体**——私聊是项目内的私下沟通，不是独立于项目之外的秘密通道；
2. **团队协作需要信息完整**——私聊里给的背景，项目经理不知道，拆解和核对就会失真；
3. **避免「黑箱沟通」**——从机制上杜绝「绕过项目经理达成约定」的可能。

所以它的定位很明确：**适合「不想刷屏但希望团队成员知道」的场合，不适合「不想让项目经理知道」的场合。**

## 哪条私聊写回，哪条不写回

「私聊写回项目记忆」针对的是**项目内的私聊**。Knowe 里有两类私聊，归属不同：

| 私聊 | 写回项目记忆？ | 说明 |
|:--|:--|:--|
| **群内私聊**（`dm:项目:成员`，双击花名册成员进入） | **写回** | 属于项目上下文，项目经理始终知道 |
| **知知（Zinnia）平台私聊**（左侧会话列表顶部的固定窗口） | **不写回** | 不属于任何项目，是独立的接待通道（见[10 核心概念 · 知知 · 项目经理 · 成员](10-02-知知-项目经理-成员.md)） |

一句话：**「私聊不隐秘」说的是项目内私聊；和知知的平台私聊是另一回事。** 操作面的边界说明见[20 使用指南 · 群聊与私聊 · 「私聊不隐秘」：边界说明](20-04-群聊与私聊.md#私聊不隐秘边界说明)。

## 私聊内容在记忆里的位置

写回的不是一个「私聊小本本」，而是**项目记忆本身**——私聊内容与群聊消息一视同仁，进入三层结构：

| 层 | 私聊内容的位置 |
|:--|:--|
| **最近活动** | 新发的私聊消息进入最近活动，优先装进上下文 |
| **滚动摘要** | 随时间推进，旧私聊内容被压缩进滚动摘要，保持全局感 |
| **历史活动段** | 更早的私聊记录归档保存，需要时可回溯 |

（三层结构的完整解释见[10 核心概念 · 记忆与上下文 · 项目记忆的三层结构](10-05-记忆与上下文.md#项目记忆的三层结构)。）换句话说，私聊消息和群聊消息一样，可以被后续上下文引用、也可以被回溯——它在记忆里的地位没有任何「降级」。

## 三类权限边界：沙箱、记忆与工具

每个对象（知知 / 项目经理 / 成员 / 群）的资料页上都有一段权限边界说明，按三个维度讲（入口见[20 使用指南 · 搜索、收藏与联系人 · 联系人资料页](20-07-搜索收藏与联系人.md#联系人资料页)）。本页把每个维度展开：

| 维度 | 管什么 | 边界在哪 |
|:--|:--|:--|
| **沙箱** | 能读写**哪些文件** | 默认只在工作区目录内，「出不去」（见[10 核心概念 · 项目与工作区 · 工作区目录：AI 的沙箱](10-03-项目与工作区.md#工作区目录ai-的沙箱)）；你亲手拖进聊天输入区的附件是例外入口——且只有经应用「亲眼确认并签名」的路径才会被读取（见[20 使用指南 · 文件与附件 · 安全护栏](20-05-文件与附件.md#安全护栏只有你亲手选的文件才会被读取)） |
| **记忆** | 能看到**哪些上下文** | 项目记忆（三层结构）+ 知识库（全局 / 项目两级作用域，见[20 使用指南 · 知识库与技能包 · 两级作用域](20-06-知识库与技能包.md#两级作用域全局与项目)）；私聊内容属于项目记忆的一部分 |
| **工具** | 能调用**哪些能力** | 成员的工具箱——每个成员完全相同（**工具一样，脑子不一样**，见[10 核心概念 · 知知 · 项目经理 · 成员 · 工具一样，脑子不一样](10-02-知知-项目经理-成员.md#工具一样脑子不一样)） |

为什么资料页要放这个？因为 Knowe 里「能做什么」是有明确边界的，你随时能查、不用靠猜（[20 使用指南 · 搜索、收藏与联系人 · 权限边界](20-07-搜索收藏与联系人.md#权限边界沙箱记忆与工具)）。

## 哪些内容会被脱敏

脱敏处理的是**内部标识**，让你看到的是可读信息而不是机器标识：

- **成员内部 id**——界面自然语言里一律脱敏，你看到的是成员名字，不是内部标识；
- **内部路径**——同样的规则：界面展示可读路径，内部路径不直接暴露；
- **API Key**——仅保存在本机、不写入浏览器存储（见[30 配置 · 模型与提供方 · API Key 的安全说明](30-01-模型与提供方.md#api-key-的安全说明不落盘)）；界面中涉及 Key 的画面遵循打码 / 留空规范。

此外在工程层面，渲染进程不直接持有 Node 能力（contextIsolation）——界面层无法绕过应用边界直接操作本机资源，这是 Knowe 隐私设计的另一道边界。

> **边界**：完整机制（记忆投影里包含什么、脱敏规则的完整清单）见[80 支持 · 安全与隐私](80-01-安全与隐私.md)。

## 常见问题

**问：私聊既然写回记忆，那私聊还有什么意义？**
有。它适合「不想刷屏但希望团队成员知道」的场合——单独给某位成员补充背景、交代一段上下文；只是别拿它当秘密通道。

**问：和知知的平台私聊会被写回某个项目吗？**
不会。知知的平台私聊不属于任何项目，是独立的接待通道（见[10 核心概念 · 知知 · 项目经理 · 成员](10-02-知知-项目经理-成员.md)）。

**问：成员到底能碰我机器上的哪些文件？**
默认只有工作区目录；你亲手拖进输入区的附件是例外入口，而且只有经应用确认的路径才会被读取（[20 使用指南 · 文件与附件 · 安全护栏](20-05-文件与附件.md#安全护栏只有你亲手选的文件才会被读取)）。

**问：脱敏会把我的聊天内容也打码吗？**
不会。脱敏针对的是成员内部 id、内部路径这类**内部标识**，不是你的聊天内容——聊天内容按项目记忆的规则存放与使用。
